# sextant_lc on LEZ v0.4 (the actor model)

Branch `v0.4` ports the light client to LEZ `v0.4.0-rc3` (logos-execution-zone
tag `v0.4.0-rc3`, commit `bafd07be`, 2026-11-11), the latest release candidate
of the v0.4 line. Nothing here is merged into `main`; the v0.3 program,
binaries and evidence on `main` are unchanged. Everything new lives under
[`v04/`](../v04) and [`vectors/sepolia-v04/`](../vectors/sepolia-v04).

## 1. What v0.4 changes for the light client

v0.3 ran a program's `plan` once over a list of account rows, then `apply`
once per effect on those rows. v0.4 replaces this with **actors**: an actor is
an account paired with a program; a run handles **one message to one actor**
and may change **only that actor's state**; everything else is a message to
another actor, synchronous (same transaction, depth first, a refusal anywhere
fails the transaction) or asynchronous (`lee/state_machine/core/src/program/mod.rs`
at the tag: `ReceiveInput`, `Response`, `actor_entrypoint!`). A program cannot
read another actor's state; it can read its own. A public transaction is one
root call to one actor, which declares every actor it reaches; a fresh account
is reached only if the delivering message carries a PDA seed of the sending
program or the transaction carries admission evidence for it.

Between `v0.4.0-rc1` (the tag Portage's spike first used) and `rc3`, the
changes that touch a program are: the clock (PR #988, "single clock actor": one
clock actor, read by message, `ReadTimestamp`/`ReadBlockId` with a
granularity), the program loader (tagged `LoaderEntry` state, and loader reads
charged at one cycle per byte), and fees on outbound cross-zone sends. The
program ABI a guest sees (`ReceiveInput`, `Response`, validity windows) is the
same. Sextant needs no clock read: its weak-subjectivity bound is a timestamp
**validity window** on the response (`Response::timestamp_window`), which the
state machine checks at settlement, exactly as v0.3's plan window did.

## 2. The port

The verification is sextant-core, unchanged: the same `lc::bootstrap`,
`lc::prepare`, `bl::miller`, `bl::final_is_one`, `statement::evaluate`. The
accounts are the same PDAs with the same seeds (instance `[instance_id]`, job
`sha256("job" ‖ instance_id ‖ job_id)`, header `sha256("header" ‖ instance_id
‖ slot)`), and the job id is the same `sha256(digest(instance) ‖
digest(update))`. Every refusal keeps its v0.3 code.

```text
Init    root → instance(Init)   → header(Record)
Begin   root → instance(Begin)  → job(Open)          every check but the pairing
Miller  root → job(Miller)                           the two Miller loops
Finish  root → job(Finish)      → instance(Advance) → header(Record)
                 final exponentiation; the job is spent
Attest  root or a consumer → header(Attest)
Update  private root → instance(Advance) → header(Record)       (section 6)
```

What the actor model changed in the design:

- **The instance reads its own store.** On v0.3 a plan could not read
  accounts, so `Begin` carried the whole instance and `apply` compared
  digests. On v0.4 the instance actor runs `Begin` itself on its own state;
  `Begin` carries only `current`, the digest the operator built against
  (`E7293` if the instance moved on). `Begin` shrinks by the instance (about
  400 bytes; 51,826 bytes with a committee handoff).
- **The job holds the next instance.** `Finish` carries nothing but the job's
  address: the job runs the final exponentiation and sends `Advance { prev,
  next }` to the instance, which checks `prev` against the digest of its own
  state (`E7293`), writes `next`, declares the staleness window and records
  the header. A competing operator's second job from the same store is
  refused there (test `two_jobs_racing_from_one_store_land_once`).
- **Who may write.** `Open`, `Advance` and `Record` are decoded only when the
  sender is another actor of this program (`ReceiveInput::from_own_program`);
  from a transaction or another program they are not a message at all
  (`E7201`, test `internal_messages_are_refused_...`). Each handler also
  checks that it runs at the PDA its arguments name (`E7290`), so an instance
  cannot be created at an arbitrary account.
- **Records that do not exist are not actors.** A header slot never recorded
  is an account that does not exist, so a consumer's `Attest` to it fails its
  transaction before the program runs (unadmitted actor); with PDA evidence in
  the transaction it reaches the empty record and is refused `E7292`. The same
  holds for `Miller`/`Finish` on a job never opened (`E7294`).
- **Events** are attributed to the program's account (rc3's
  `TransactionEvent::account_id` is the program, not the actor).
- **`Attest` is variant 0** of the message enum, so a consumer (Portage's
  wrap_bridge) encodes it with a one-variant enum of its own.

## 3. Tests on rc3's state machine

`cargo test --release --manifest-path v04/executor-tests/Cargo.toml` runs the
committed binary through `lee::V03State` at `v0.4.0-rc3`
(`ValidatedStateDiff::from_public_transaction_metered`, the call the
sequencer's settlement makes), every step signed by an account the chain has
never seen. **22 tests**, on real vectors:

- `program.rs` (mainnet, periods 1881 to 1884): the lifecycle through three
  handoffs and a finality update, ending at the native verifier's store; the
  configuration written once (`E7291`); Init refusals (`E7215` checkpoint
  mismatch, `E7212` committee branch, `E7201` participation floor); internal
  messages refused from a transaction; **a tampered signature** refused at
  `Finish` (`E7203`) with nothing moved; **fabricated updates** refused at
  `Begin` before any job exists: **low participation** (`E7205`), a committee
  never handed off (`E7204`), a header not finalized (`E7202`), an execution
  root not under the body (`E7211`), another committee (`E7213`); a tampered
  key witness (`E7214`); **replays**: a competing operator (`E7293`, `E7294`,
  then `E7210` already applied), two jobs racing from one store; steps out of
  order (`E7294`, `E7295`, `E7291`); a stalled instance resuming; attestations
  and their refusals: predicate false (`E7208`), **another chain** (`E7209`),
  bad inclusion (`E7207`), no record (`E7292`), another slot's record
  (`E7290`); attestations against the checkpoint's header; `E7206` against the
  chain itself and the clock's window; and `Update` sent as a public
  transaction refused over the cap.
- `testnets.rs`: Hoodi (Fulu, periods 505 to 508), Sepolia (Gloas, 1385 to
  1388), one Sepolia instance across the Gloas fork, the fresh Sepolia set
  (1410 to 1413) and the checkpoint of the Portage vault deposit.

(`E7206` and Gloas, ImageID `ad6fbedb…`) through `lee::V03State` at v0.3.0
([`raw/measure-lez-2026-10-17-v2.txt`](raw/measure-lez-2026-10-17-v2.txt)),
v0.4 the committed v0.4 binary at rc3
([`raw/v04-measure-lez.txt`](raw/v04-measure-lez.txt)). Cycles are the
execution gas a transaction is charged (`MAX_GAS_EXEC` = 10,000,000).

| message | v0.4.0-rc3 | v0.3.0 (`v2`) | change |
|---|---:|---:|---:|
| `Init` from the checkpoint (slot 15,409,152) | 1,816,989 (2 runs) | 1,835,474 | -1.0% |
| update 1 (period 1881, handoff): `Begin` | 5,390,861 (2 runs) | 5,474,785 | -1.5% |
| update 2 (period 1882, handoff): `Begin` | 5,436,361 | 5,346,523 | +1.7% |
| update 3 (period 1883, handoff): `Begin` | 5,428,167 | 5,390,598 | +0.7% |
| update 4 (period 1884, finality): `Begin` | 3,650,261 | 3,664,393 | -0.4% |
| `Miller` | 4,217,445 (1 run) | 4,217,768 | -0.0% |
| `Finish` | 3,751,508 to 3,753,893 (3 runs) | 3,767,505 to 3,769,621 | -0.4% |
| one update with a handoff, three transactions | 13,362,199 (period 1881) | 13,462,174 | -0.7% |
| `Attest`: WETH balance slot ≥ 1 wei (storage proof) | 216,428 | 304,478 | -28.9% |

| heaviest step, share of the cap | 54.4% | 54.7% | |

The light client's own work dominates and does not move: the same
sextant-core, the same toolchain (both binaries are RISC Zero `r0.1.91.1`
Docker builds). What moves is the shell: `Attest` is about 30% cheaper (one
actor run that reads its record, against v0.3's plan plus an apply); a v0.4
`Begin` no longer carries and hashes the instance but runs two guests (the
instance, then the job it opens), and lands within 2% of v0.3 either way;
`Finish` is three runs (job, instance, header) for slightly less than v0.3's
three applies. Built with the local toolchain instead of Docker, the same
source is about 5% cheaper (`Begin` 5,115,064), a toolchain effect: the table
uses the committed, reproducible build. The split of decision D2 is still
required: the whole update is 12.85M cycles in one run (section 6), over the
10M cap.

On the fresh Sepolia set (periods 1410 to 1413, the sequencer run of section 5)
the heaviest `Begin` is 5,562,017 cycles (55.6%).

## 5. A local rc3 sequencer, end to end

[`v04/scripts/e2e-seq.sh`](../v04/scripts/e2e-seq.sh) builds a home for a
standalone `sequencer_service` of `v0.4.0-rc3` (`--features standalone`, mock
Bedrock, 2 s blocks), funds the driver's fee payer at genesis, and runs it with
`RISC0_DEV_MODE=0`. The driver (`v04/executor-tests` `--bin seq_drive`) loads
the committed binary through the program loader, then sends signed,
fee-declaring transactions over JSON-RPC. The clock is real time (2026-11-14),
so the instance is initialised from a fresh Sepolia checkpoint
(`vectors/sepolia-v04`, fetched read-only that day by
`scripts/fetch-vectors.py sepolia`: checkpoint slot 11,550,720 of period 1410,
updates of 1410 to 1412 and a finality update in 1413, execution block
12,134,154), with the default two-week bound.

Evidence: [`evidence/v04-seq/manifest.tsv`](../evidence/v04-seq/manifest.tsv)
(label, expected verdict and code, verdict, block, index, hash, bytes),
[`run.txt`](../evidence/v04-seq/run.txt),
[`verify.txt`](../evidence/v04-seq/verify.txt), every block of the run
(`blocks/9.borsh` to `36.borsh`, as `getBlock` returned them). Program
`D9NCt9wCCDJuVii6EW8fnJwyiGbfm8s2HxxMJNBYTaUD` (7 loader transactions:
6 segments and an immutable header), then 28 transactions, **18 applied and
10 reverted, each as expected**:

| step | transactions | verdict |
|---|---|---|
| `Init` from the Sepolia checkpoint (period 1410) | 1 | applied |
| `Init` again at the same id | 1 | reverted, `E7291` |
| `Init` from the mainnet checkpoint of 2026-10-11, the same two-week bound | 1 | reverted by the clock (window closed 2026-10-25) |
| a tampered signature (update 1 signed by update 2's signature): `Begin`, `Miller`, `Finish` | 3 | applied, applied, reverted `E7203` |
| participation below the floor (341 of 512): `Begin` | 1 | reverted, `E7205` |
| update 1 (period 1410, handoff): `Begin`, `Miller`, `Finish` | 3 | applied |
| replay of update 1 built against the old store; rebuilt against the new one | 2 | reverted, `E7293`; reverted, `E7210` |
| updates 2 and 3 (handoffs), 4 (finality, period 1413) | 9 | applied |
| `Attest`: WETH `balanceOf[holder] == 0` and a log of tx 92 at the last header (execution block 12,134,154); a log of tx 0 at the checkpoint's header (block 12,106,981) | 3 | applied |
| `Attest` as a mainnet statement; `≥ 1 wei` (false); the checkpoint's receipt against the last header; a slot never recorded | 4 | reverted, `E7209`, `E7208`, `E7207`, `E7292` |

`seq_drive verify`: **100 passed, 0 failed**. Cycles of the run's steps on
rc3's state machine, from the replay: `Init` 1,815,870; `Begin` 5,498,999 to
5,562,017 with a handoff (55.6% of the cap, the heaviest step), 3,632,807
without; `Miller` 4,217,642; `Finish` 3,752,254 to 3,754,589; `Attest` 59,159
to 305,058. Each refusal is metered at the whole 10M budget the replay gives
it (no fee declared); rc3 blocks carry no per-transaction fee receipt, so what
the sequencer charged a refusal was not read back.

`seq_drive verify` is the verifier: from the sequencer alone it re-reads every
block of the manifest, checks each transaction is at its index with its hash
and that the block's `reverted` list gives the expected verdict, **replays
every Sextant transaction** (the same root call, declared actors and evidence,
from a fresh signer, at the block's timestamp) on a fresh in-memory rc3 state
with the same binary and checks the same verdict and **the same refusal
code** (a v0.4 block carries no revert reason), then reads the instance and
every header record back with `getAccountView` and compares them with the
native verifier's store and records and with the replay's state, byte for byte.

Two facts of rc3 the run shows. A transaction whose validity window has closed
(the stale mainnet `Init`) is **included, charged and reverted**, not dropped:
the window is checked at settlement. And a refused transaction stays in its
block, listed in `reverted`.

`RISC0_DEV_MODE=0` on the sequencer means it would refuse a fake receipt; a
public transaction carries none (the sequencer executes it), so the proofs of
this path are the per-step receipts of section 7 and the private-proof update
of section 6, a real proof the state machine verifies.

## 6. The private-proof update

An update proven off-chain as one privacy-preserving transaction, with one
public effect. A fresh private account's actor of sextant_lc receives
`Update` (the whole verification, pairing included) inside the
privacy-preserving circuit (`lee::execute_and_prove`), and sends `Advance` to
the public instance across the boundary. rc3 presents a private sender to a
public actor with its program kept (`execution_state.rs`, `sender()`), so the
public instance accepts it as one of its own program's actors, checks the
digest of its own state, writes the next store and records the header, exactly
as after `Finish`. No step of it is bounded by the 10M public cap: a private
run is proven, not metered.

Measured with the committed binary, real proof (`RISC0_DEV_MODE=0`), on the
mainnet vectors' update 1 (period 1881, with a handoff),
[`raw/v04-private-update.txt`](raw/v04-private-update.txt):

| | |
|---|---:|
| the private run (`Update`: the whole verification, pairing included) | 13,123,590 user cycles, 14,155,776 total, 14 segments |
| proving, the whole transaction (the program run, the privacy circuit, one succinct proof) | 1,910.5 s wall (31.8 min), 8.66 GB peak resident |
| the transaction | 227,525 bytes (the message the private actor receives: 52,197) |
| verification and settlement by the state machine | 0.13 s |
| public effect | the instance's store advanced (the period-1882 committee; update 1 keeps the finalized header), the header record written |
| the same transaction again | refused: its commitment is already in the state |

The public path proves nothing (the sequencer executes it): its three
transactions are 13.1M cycles of sequencer execution. Proven step by step
(section 7), the same update is 26 minutes of proving in three receipts; here
it is 32 minutes for one receipt that also carries the privacy circuit, which
the state machine checks in a fraction of a second.

What the public path does not need and this one does: the fee. A sequencer
(`lez/chain_state/src/classify.rs`) admits a private transaction only if
exactly one native credit to the fee inbox crosses the boundary, from a funded
private payer whose key the prover holds (`MissingPrivateFee`). That is one
more private account and one native-token run in the same proof, small next to
the update; the measurement settles with lee's
`transition_from_privacy_preserving_transaction`, the state machine's own
verification, without it. A sequencer prices the transaction at
`PRIVATE_VERIFY_GAS` = 409,764 execution gas plus the public part (the
instance's `Advance` and the header's `Record`), against 13.1M over three
transactions on the public path, and at `PRIVATE_GAS_STOR` = 224,063 storage
gas: at most four private transactions per block
(`lez/programs/fee/core/src/market.rs`).

The trade: one transaction and about 0.5M gas instead of three and 13.1M, for
about 32 minutes and 8.7 GB of proving on the operator's machine instead of the sequencer's
execution. Anyone can still submit an update. Two proofs built from the same
store would land once: the second reaches `Advance` with a digest the instance
no longer has (`E7293`, the path `two_jobs_racing_from_one_store_land_once`
tests for jobs; not run for two proofs).

## 7. Real proving per step

`RISC0_DEV_MODE=0 cargo run --release --manifest-path v04/executor-tests/Cargo.toml --bin prove`
proves the actor run of each step that v0.4 executes, from the committed
binary: the guest session of one framed `ReceiveInput`, committing one
`Transition` ([`raw/v04-prove.txt`](raw/v04-prove.txt); segments of 2^20,
8.68 GB peak resident, on the same machine as v0.3's figures).

| actor run (v0.4 binary) | user cycles | total cycles | segments | prove (s, wall) | succinct receipt (bytes) | v0.3 (s, wall) |
|---|---:|---:|---:|---:|---:|---:|
| `Begin` at the instance, period 1882 with handoff | 5,408,034 | 6,291,456 | 6 | 655.8 | 330,145 | 690.7 |
| `Miller` at the job | 4,217,445 | 4,718,592 | 5 | 490.0 | 228,785 | 544.4 |
| `Finish` at the job (final exponentiation) | 3,691,783 | 4,194,304 | 4 | 420.8 | 227,855 | 476.9 |
| `Attest` at a header record (ERC-20 `Transfer` log) | 62,572 | 131,072 | 1 | 63.9 | 226,323 | 48.4 |

An update is 1,566.6 s of proving in three receipts (26.1 minutes; v0.3
1,712.0 s, with segments of 2^18, [`BENCHMARKS.md`](BENCHMARKS.md) section 3).
`Begin`'s receipt is the largest because the journal (the committed
`Transition`) carries its input, two 512-key committees. On the public path no
one has to produce these receipts: the sequencer executes public transactions.
They are the cost of proving each step (P.2), and the private-proof update of
section 6 is the same work in one receipt.

## 8. Gaps

- **Testnet 0.4** does not exist yet; nothing here ran on a public network.
- The private-proof update is measured and settled at the state machine, not
  sent to the sequencer: the fee leg (a funded private payer) is not built.
- `Attest` from a consumer is exercised by Portage's v0.4 branch
  (edenbd1/lez-portage `v0.4-spike`), not by a consumer program in this
  repository: `programs/erc20_receiver` is not ported.
- The client (`cli/`) is v0.3 only; on v0.4 the driver is `seq_drive`.
