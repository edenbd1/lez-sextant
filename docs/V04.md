## 1. What v0.4 changes for the light client

v0.3 ran a program's `plan` once over a list of account rows, then `apply`
once per effect on those rows. v0.4 replaces this with **actors**: an actor is
an account paired with a program; a run handles **one message to one actor**
and may change **only that actor's state**; everything else is a message to
another actor, synchronous (same transaction, depth first, a refusal anywhere
fails the transaction) or asynchronous (`lee/state_machine/core/src/program/mod.rs`
at the tag: `ReceiveInput`, `Response`, `actor_entrypoint!`). A program cannot
read another actor's state; it can read its own. A public transaction is one
root call to one actor, which declares every actor it reaches; a fresh account
is reached only if the delivering message carries a PDA seed of the sending
program or the transaction carries admission evidence for it.

Between `v0.4.0-rc1` (the tag Portage's spike first used) and `rc3`, the
changes that touch a program are: the clock (PR #988, "single clock actor": one
clock actor, read by message, `ReadTimestamp`/`ReadBlockId` with a
granularity), the program loader (tagged `LoaderEntry` state, and loader reads
charged at one cycle per byte), and fees on outbound cross-zone sends. The
program ABI a guest sees (`ReceiveInput`, `Response`, validity windows) is the
same. Sextant needs no clock read: its weak-subjectivity bound is a timestamp
**validity window** on the response (`Response::timestamp_window`), which the
state machine checks at settlement, exactly as v0.3's plan window did.

## 2. The port

The verification is sextant-core, unchanged: the same `lc::bootstrap`,
`lc::prepare`, `bl::miller`, `bl::final_is_one`, `statement::evaluate`. The
accounts are the same PDAs with the same seeds (instance `[instance_id]`, job
`sha256("job" ‖ instance_id ‖ job_id)`, header `sha256("header" ‖ instance_id
‖ slot)`), and the job id is the same `sha256(digest(instance) ‖
digest(update))`. Every refusal keeps its v0.3 code.

```text
Init    root → instance(Init)   → header(Record)
Begin   root → instance(Begin)  → job(Open)          every check but the pairing
Miller  root → job(Miller)                           the two Miller loops
Finish  root → job(Finish)      → instance(Advance) → header(Record)
                 final exponentiation; the job is spent
Attest  root or a consumer → header(Attest)
Update  private root → instance(Advance) → header(Record)       (section 6)
AttestPrivate  private root or a consumer's private actor
          → private actor(AttestPrivate) → instance(CheckRoot)  (section 8)
```

What the actor model changed in the design:

- **The instance reads its own store.** On v0.3 a plan could not read
  accounts, so `Begin` carried the whole instance and `apply` compared
  digests. On v0.4 the instance actor runs `Begin` itself on its own state;
  `Begin` carries only `current`, the digest the operator built against
  (`E7293` if the instance moved on). `Begin` shrinks by the instance (about
  400 bytes; 51,826 bytes with a committee handoff).
- **The job holds the next instance.** `Finish` carries nothing but the job's
  address: the job runs the final exponentiation and sends `Advance { prev,
  next }` to the instance, which checks `prev` against the digest of its own
  state (`E7293`), writes `next`, declares the staleness window and records
  the header. A competing operator's second job from the same store is
  refused there (test `two_jobs_racing_from_one_store_land_once`).
- **Who may write.** `Open`, `Advance` and `Record` are decoded only when the
  sender is another actor of this program (`ReceiveInput::from_own_program`);
  from a transaction or another program they are not a message at all
  (`E7201`, test `internal_messages_are_refused_...`). Each handler also
  checks that it runs at the PDA its arguments name (`E7290`), so an instance
  cannot be created at an arbitrary account.
- **Records that do not exist are not actors.** A header slot never recorded
  is an account that does not exist, so a consumer's `Attest` to it fails its
  transaction before the program runs (unadmitted actor); with PDA evidence in
  the transaction it reaches the empty record and is refused `E7292`. The same
  holds for `Miller`/`Finish` on a job never opened (`E7294`).
- **Events** are attributed to the program's account (rc3's
  `TransactionEvent::account_id` is the program, not the actor).
- **`Attest` is variant 0** of the message enum, so a consumer (Portage's
  wrap_bridge) encodes it with a one-variant enum of its own.

The light client's own work dominates and does not move: the same

actor run that reads its record, against v0.3's plan plus an apply); a v0.4
`Begin` no longer carries and hashes the instance but runs two guests (the
instance, then the job it opens), and lands within 2% of v0.3 either way;
`Finish` is three runs (job, instance, header) for about v0.3's three
applies. The v0.4 instance also keeps the record index (section 8): `Init`
and every `Advance` that records a header append its leaf and recompute the
root (about 40,000 cycles), and the instance carries the index (1,187 bytes
instead of 403), which `Begin` hashes; the binary before the index
(ImageID `bf3df59e…`) was 1.0% to 1.5% cheaper per step. Built with the local toolchain instead of Docker, the same
source is about 5% cheaper (`Begin` 5,115,064), a toolchain effect: the table
uses the committed, reproducible build. The split of decision D2 is still
required: the whole update is over 13M cycles in one run (section 6), over
the 10M cap.

On the fresh Sepolia set (periods 1410 to 1413, the sequencer run of section 5)
the heaviest `Begin` is 5,562,017 cycles (55.6%).

## 6. The private-proof update, on the sequencer

An update proven off-chain as one privacy-preserving transaction, with one
public effect, **submitted to the local rc3 sequencer, included in a block and
read back**. A fresh private account's actor of sextant_lc receives `Update`
(the whole verification, pairing included) inside the privacy-preserving
circuit (`lee::execute_and_prove`), and sends `Advance` to the public instance
across the boundary. rc3 presents a private sender to a public actor with its
program kept (`execution_state.rs`, `sender()`), so the public instance accepts
it as one of its own program's actors, checks the digest of its own state,
writes the next store, appends to its record index and records the header,
exactly as after `Finish`. No step of it is bounded by the 10M public cap: a
private run is proven, not metered.

**The fee leg.** A sequencer admits a private transaction only if exactly one
native credit to the fee inbox crosses the boundary, from a private payer
witnessed in the same proof (`lez/chain_state/src/classify.rs`,
`MissingPrivateFee`). `seq_drive private` builds it as rc3's wallet does
(`lez/wallet/src/lib.rs`):

- the payer is one of the two private accounts LEZ's `networks/local.json`
  funds at genesis (`supply_private_account`, the local network's
  `testnet_initial_state` keys; only these can be funded at genesis, their
  recovery bindings are pinned in rc3's initial state). Genesis leaves a
  pending native credit; the **same transaction claims it**
  (`ProvingInput::claims`, the credit's path from `getMessagePath`), so the
  payer needs no transaction of its own first;
- the fee inbox is a declared public actor; `ProvingInput::fee` debits the
  payer's reserve to it; the payer is presented under a fresh blinded alias
  with a recovery entry, so settlement returns the unspent reserve to the
  alias, not to a linkable address; the sextant actor is presented blinded too;
- the reserve is priced off a simulation of the public part
  (`simulate_privacy_preserving_transaction`) at the base fees of
  `getFeeState`, with headroom for the half hour of proving (eight times the
  base fees, half again the cycles), and never below the fee at head.

## 8. The private consumer path: the record index

A consumer that attests in public names the header record it reads: `Attest`
is a message to the record's actor, `sha256("header" ‖ instance_id ‖ slot)`,
so the transaction says which Ethereum block the consumer cares about. The
private path hides that. Implemented in the program and tested on rc3's state
machine ([`tests/private.rs`](../v04/executor-tests/tests/private.rs)), and
run on the sequencer with a real proof (section 6).

**The index.** Every instance keeps an append-only Merkle tree over the header
records it writes (`Index` in
[`lib.rs`](../v04/programs/sextant/src/lib.rs)): SHA-256, depth 20 (about a
million records), the deposit-contract construction (a frontier of 20 nodes,
empty subtrees from zero leaves), the leaf of a record
`sha256("sextant_lc/v0.4/record" ‖ borsh(record))`. `Init` appends the
checkpoint's record; every `Advance` whose finalized header is new appends
its record (an update that keeps the finalized header appends nothing). The
instance keeps its last 16 roots, newest last. The index lives in the instance
itself, so it moves only with the instance, under the same digest check
(`E7293`): no other actor can write it. A consumer rebuilds the tree from the
records the instance wrote, in order (the header records it reads back, or the
`Record` messages of the instance's transactions), so a path needs no help
from anyone.

**The attestation.** `AttestPrivate { instance_id, root, position, record,
path, query }` goes to a **private** actor of sextant_lc, as the root of a
privacy-preserving transaction or from a consumer program's private actor. In
the proof, it refuses unless the record's leaf at `position` hashes up `path`
to `root` (`E7297`) and the query holds against the record (`statement::evaluate`,
the same check and codes as `Attest`: `E7207`, `E7208`, `E7209`). It then sends
`CheckRoot { instance_id, root }` to the public instance, which refuses unless
`root` is one of its last 16 (`E7296`). A record once under a root stays under
every later one (the tree only grows), so the window of 16 only bounds how
stale a proof may be when it settles; a consumer whose root has dropped out
rebuilds the path against the current root.

**What is public.** The transaction's public part is the fee crossing and one
`CheckRoot` to the instance: the instance id and a root that every consumer of
that instance shares until the next new header. The record, its slot and
position, the Ethereum proof and the predicates stay in the proof. The test
`a_private_attestation_reveals_the_instance_and_a_root_not_the_record` checks
the boundary carries exactly one message, `CheckRoot` to the instance; that
the instance is the only public actor declared; and that none of the record's
roots, its leaf, or any header account's address appears anywhere in the
transaction's bytes. The private actor is a fresh private account of
sextant_lc, presented blinded: its commitment and nullifier link to nothing.
The anonymity set is every record of the instance under the root: on mainnet
an instance writes one to a few records per sync-committee period (27 hours).

**What a consumer program does.** Its own private actor sends `AttestPrivate`
synchronously to a private actor of sextant_lc it creates in the same
transaction (a refusal anywhere fails the transaction, so the consumer runs on
only if the statement holds), and checks the callee's program is sextant_lc
(`Actor::program_account_id`). The tests send it as the root call; a consumer
guest that forwards it is not built in this repository (section 11).

## 10. Operators in contention

Anyone may submit an update, so several operators may race on the same one.
What makes that safe is the job binding: the job id is
`sha256(digest(instance) ‖ digest(update))`, and its content (the next
instance, the pairing inputs) is computed by the instance from its own state
at `Begin`. Every operator who starts the same update from the same store
reaches the same job, with the same content; anyone can continue anyone's
job; nobody can put anything else at that address (`Open` is an internal
message, `E7201` from a transaction, and refuses different content, `E7291`).

**What happens when they race** (on the state machine,
[`tests/operators.rs`](../v04/executor-tests/tests/operators.rs)):

| step raced | first submission | every later one, same store |
|---|---|---|
| `Begin` | opens the job | applied, a no-op (the job is already there, identical) |
| `Miller` | runs the Miller loops | reverted `E7295` (step done) |
| `Finish` | advances the instance, records the header, spends the job | reverted `E7294` (no job) |
| `Begin` after the update landed | | `E7293` (built against the old store), `E7210` rebuilt against the new one |
| a private whole-update proof from the same store | settles | refused at `Advance`, `E7293` (section 6) |

The instance moves once, whatever the order: `four_operators_in_random_interleavings_land_each_update_once`
runs four operators that submit `Begin`, `Miller`, `Finish` blindly, scheduled
by a seeded generator (three seeds), and checks exactly one `Miller` and one
`Finish` apply, every other submission reverts with a code meaning "done" (or
is not admitted: a spent job no longer exists), and the instance ends at the
native verifier's store. A refused submission still costs its sender: rc3
charges a transaction whose program panics its **whole declared execution
budget** (`charged_cycles`, `lee/state_machine/src/validated_state_diff`), so
three operators submitting every step blindly spend about 50M cycles on the
losing submissions for a 13.4M-cycle update (`three_operators_submitting_every_step_land_the_update_once`).

**The policy** an update operator follows (the tests run rules 1 and 2):

1. Build the update against the instance's current store and read the chain
   before every submission: if the instance's digest is no longer the one the
   update was built against, stop (it landed, or another update did: rebuild).
2. If the job exists, send its next step (`Miller` if it has no Miller product,
   else `Finish`), whoever opened it; otherwise `Begin`.
3. Declare a tight gas limit per step (the step's measured cycles plus a
   margin: about 5.6M for `Begin`, 4.3M for `Miller`, 3.9M for `Finish`), so
   that a race lost in the mempool costs that step, not the block's cap.
4. Defer by rank: operator k of n waits k blocks after a new update is
   published before its first submission and re-reads; the first operator
   does all three steps, the others only take over a job that stalls.
5. A private-path operator (section 6) proves for about 30 minutes: before
   proving and again before submitting it checks the instance's digest, and
   drops its proof if a public job of the same update has reached `Miller`
   (that job lands first).

`operators_following_the_deferral_policy_finish_each_others_job_with_no_refusal`
runs rules 1 and 2 with three operators taking turns over all four mainnet updates:
each update lands in exactly three applied transactions (A `Begin`, B
`Miller`, C `Finish`) with no refusal.

**Griefing.** `a_griefer_can_neither_block_nor_poison_an_honest_job`: a forged
update (another header's signature) from the same store passes `Begin` and
`Miller` (the pairing is `Finish`'s) but at another job id, and its `Finish`
fails the pairing (`E7203`); a `Begin` claiming a store the instance does not
hold is `E7293`; writing the honest job's address directly is not a message
the program accepts; front-running the honest operator's `Miller` only does
its work for it, and the honest `Finish` lands. What a griefer can do is spend
its own fees: a forged update costs it `Begin` and `Miller` (about 9.7M
cycles, nearly a block's execution gas, at a base fee that rises with
congestion) and delays nothing but block space. Refusing at `Finish` is the
price of splitting the pairing (decision D2); the private path has no such
window, since a forged update fails inside the proof and never reaches the
chain.

## 11. Gaps

- **Testnet 0.4** does not exist yet; nothing here ran on a public network.
- A consumer program that forwards `AttestPrivate` from its own private actor
  is not built here (the tests and the sequencer run send it as the root
  call), and `programs/erc20_receiver` is not ported; `Attest` from a consumer
  program is exercised by Portage's v0.4 branch (edenbd1/lez-portage
  `v0.4-spike`).
- The private consumer path reveals the instance and a shared root; hiding the
  instance too would need a root shared across instances (an index of
  indexes), not built.
- Refusals panic, so a losing racer is charged its whole gas limit (section
  10); a refusal that exits with a code would be charged the cycles it used.
- The real per-step proving of section 7 was measured on the binary before the
  record index (ImageID `bf3df59e…`); the index adds about 1% per step.
- The client (`cli/`) is v0.3 only; on v0.4 the driver is `seq_drive`.
